# Stakeholder & Requirements: 干系人需求与功能定义

## 1. 干系人分析

### 1.1 主要干系人矩阵

| 干系人 | 角色 | 核心诉求 | 影响力 | 参与方式 |
|--------|------|---------|--------|---------|
| 中医师 | 最终用户 | 临床用药参考，高可信度 | 高 | 需求调研，UAT |
| 执业药师 | 最终用户 | 用药安全，证据支撑 | 高 | 需求调研，UAT |
| 研究者 | 最终用户 | 学术研究，知识发现 | 中 | 需求调研 |
| 普通用户 | 最终用户 | 健康知识，易懂易用 | 中 | 问卷调研 |
| 专家用户 | 质量保障 | 审查效率，反馈机制 | 高 | 审查工作台设计 |
| 项目发起人 | 赞助商 | 按时交付，ROI | 高 | 定期汇报 |
| 开发团队 | 实现方 | 清晰需求，技术可行 | 高 | Sprint Planning |

### 1.2 干系人需求详细

#### 中医师

**核心需求**:
- 快速获取可靠的药材功效信息
- 了解药材间的相互作用
- 获取临床用药参考依据

**约束条件**:
- 场景多为诊疗过程中，时间有限
- 需要可打印/导出的参考文档
- 需要专业术语与通俗解释并存

#### 执业药师

**核心需求**:
- 审核处方的用药安全性
- 快速查询药物相互作用
- 获取用药禁忌信息

**约束条件**:
- 工作场景要求高准确性
- 需要明确的警告和提示
- 需要操作日志记录

#### 研究者

**核心需求**:
- 探索药材间的潜在关联
- 获取完整的证据链
- 追踪知识来源

**约束条件**:
- 需要批量数据导出
- 需要高级筛选和查询
- 期望知识图谱可视化

#### 普通用户

**核心需求**:
- 了解中药材基础知识
- 查询药材的用法用量
- 获取健康养生建议

**约束条件**:
- 界面需要通俗易懂
- 需要安全提示（不替代医疗）
- 需要隐私保护

#### 专家用户

**核心需求**:
- 高效处理审查任务
- 便捷的修正和反馈
- 了解审查统计

**约束条件**:
- 期望批量操作功能
- 需要审查历史追溯
- 期望贡献激励机制

## 2. 功能需求定义

### 2.1 功能需求层次

```
产品需求
│
├── [MUST] 核心功能
│   ├── 智能问答
│   ├── 溯源链路展示
│   ├── 知识图谱可视化
│   ├── 药材详情页
│   └── 专家审查
│
├── [SHOULD] 重要功能
│   ├── 追问延续
│   ├── 路径探索
│   ├── 搜索功能
│   └── 审查通知
│
└── [COULD] 增强功能
    ├── 高级筛选
    ├── 证据关联网络
    └── 图谱快照
```

### 2.2 核心功能详细定义

#### F-001: 智能问答

**功能描述**: 用户通过自然语言提问，系统基于知识图谱返回可溯源的答案

**功能类型**: New Feature

**业务规则**:
- 支持中文简体提问
- 单次问答限制2000字符
- 匿名用户每分钟限5次
- 登录用户每分钟限30次

**输入**: 自然语言问题
**输出**: 结构化答案 + 实体列表 + 溯源信息

**验收标准**:
- [ ] 支持药材功效、相互作用、用法用量等类型问题
- [ ] 答案包含可点击的实体高亮
- [ ] 答案关联溯源信息 > 95%
- [ ] 响应时间 < 2秒 (P95)

---

#### F-002: 溯源链路展示

**功能描述**: 展示答案的知识来源和推理过程

**功能类型**: New Feature

**业务规则**:
- 每条答案必须关联至少一个证据
- 证据来源包括：古籍、现代研究、专家共识
- 推理链路需展示完整的实体-关系-证据链条

**输入**: 答案ID
**输出**: 推理链路可视化

**验收标准**:
- [ ] 支持展示推理链路图
- [ ] 节点可点击跳转详情
- [ ] 支持展开/折叠节点
- [ ] 支持导出推理链 (PDF)

---

#### F-003: 知识图谱可视化

**功能描述**: 提供交互式知识图谱浏览器

**功能类型**: New Feature

**业务规则**:
- 支持缩放、拖拽、筛选操作
- 节点按类型着色区分
- 支持多选和批量操作

**输入**: 初始中心节点 (可选)
**输出**: 图谱可视化界面

**验收标准**:
- [ ] 基础图谱渲染性能 > 30fps
- [ ] 支持最多500节点展示
- [ ] 支持导出图谱图片
- [ ] 支持全屏模式

---

#### F-004: 药材详情页

**功能描述**: 展示单味药材的完整信息

**功能类型**: New Feature

**业务规则**:
- 信息项包括：基原、性状、功效、主治、用法用量、禁忌、贮藏、来源
- 每个信息项可关联多个证据
- 支持版本历史查看

**输入**: 药材ID
**输出**: 药材详情页面

**验收标准**:
- [ ] 页面加载时间 < 1秒
- [ ] 所有信息项显示证据来源
- [ ] 支持历史版本对比
- [ ] 支持分享和收藏

---

#### F-005: 专家审查

**功能描述**: 专家对系统答案进行质量审核

**功能类型**: New Feature

**业务规则**:
- 专家需通过资质认证
- 审查结果：批准/修正/驳回
- 修正内容需记录历史
- 审查操作需记录操作日志

**输入**: 审查任务
**输出**: 审查结果 + 意见

**验收标准**:
- [ ] 审查任务分配公平合理
- [ ] 支持批量审查操作
- [ ] 审查响应时间 < 24小时
- [ ] 支持审查历史追溯

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 问答响应时间 | < 2秒 (P95) | 含网络延迟 |
| 图谱渲染帧率 | > 30fps | 交互流畅 |
| 页面加载时间 | < 1秒 | 首屏加载 |
| 并发用户数 | > 100 | 同时在线 |
| API可用性 | > 99.9% | 月度统计 |

### 3.2 安全需求

| 需求 | 说明 |
|------|------|
| 认证授权 | 用户需登录，专家需额外认证 |
| 数据隔离 | 用户数据隔离，机构数据隔离 |
| 审计日志 | 关键操作记录日志 |
| 隐私保护 | 个人信息加密，GDPR合规 |

### 3.3 可用性需求

| 需求 | 说明 |
|------|------|
| 浏览器支持 | Chrome, Firefox, Safari, Edge 最新两个版本 |
| 移动端 | 响应式设计，支持平板 |
| 辅助功能 | 符合WCAG 2.1 AA标准 |
| 错误处理 | 友好错误提示，支持重试 |

### 3.4 可维护性需求

| 需求 | 说明 |
|------|------|
| 监控告警 | 系统运行状态监控 |
| 日志记录 | 结构化日志，支持查询 |
| 知识更新 | 支持知识版本管理 |
| 配置管理 | 功能开关，灰度发布 |

## 4. 约束条件

### 4.1 技术约束

- 知识图谱基于 Neo4j
- 后端 API 基于 FastAPI
- 前端基于 React
- 数据库 PostgreSQL + Neo4j

### 4.2 时间约束

- MVP 开发周期: 4 Sprint (8周)
- Sprint 周期: 2周

### 4.3 资源约束

- 开发团队: 4-6人
- 专家团队: 3-5人 (兼职)
- 预算: 有限

### 5.1 关键假设

| 假设 | 影响 | 验证方式 |
