# README 产品门面改写设计

## 背景

当前根 `README.md` 信息完整，但整体更像研发仓库说明书：

- 工程现状、模块状态和接口清单占比偏大
- 首页第一感知偏“技术项目介绍”，不够像对外的正式产品门面
- 对“为什么值得关注白草”这件事，商业表达和场景痛点表达还不够聚焦

本轮用户希望把 README 简化为“产品化、面向所有人的正式门面”，并突出：

- 基于 Agent 的高效、低成本知识搜集与利用
- 在中医药这种信息密度高、人工检索成本高的场景中的价值
- 兼顾广度与深度的知识检索与探索能力
- 结果可信、可追溯、可验证

## 目标

1. 让首页首先回答“白草解决什么问题、为什么值得关注”
2. 保留中医药场景作为第一主角，Agent 作为核心差异化能力
3. 保持 README 对非开发者友好，同时保留精简技术背书和开发入口
4. 删除或下沉过细的工程状态清单，减少“内部研发报告感”

## 非目标

- 不在本轮修改项目实际功能、路线图或架构事实
- 不新增新的对外承诺或把规划能力写成已实现事实
- 不把 README 做成纯市场文案，仍保留必要的开发者入口

## 设计决策

### 决策 1：采用“场景痛点优先”的首页结构

README 首屏先讲中医药知识的真实痛点：

- 信息密度高
- 来源分散
- 关系复杂
- 人工检索、整理、比对和利用成本高

在此基础上再引出白草的产品价值，而不是先讲技术栈或系统形态。

### 决策 2：把 Agent 放在差异化能力位，而不是首页主角位

首页主语仍是“中医药知识场景”和“知识工作效率提升”。

Agent 用来解释白草为什么能：

- 更高效地搜集和整理知识
- 更低成本地复用知识工作成果
- 在多来源、多关系的上下文中做更深的关联利用

### 决策 3：把 README 收敛为“产品门面 + 精简技术背书”

保留内容：

- 一句话定位
- 场景痛点
- 核心价值
- 工作方式
- 适用对象
- 当前阶段
- 快速导航
- 快速开始与验证入口

弱化或删除内容：

- 过长的模块状态表
- 详细接口清单
- 过细路线图展开
- 大量内部研发口径

## 预期结构

1. 标题与一句话定位
2. 白草解决什么问题
3. 白草的核心价值
4. 白草如何工作
5. 适合谁
6. 当前阶段
7. 快速导航
8. 快速开始
9. 图谱与样例数据
10. 技术概览与仓库结构
11. 当前限制

## 影响范围

- `README.md`

## 验证策略

最小验证：

1. 检查 README 的标题层级与段落结构是否清晰
2. 确认快速开始命令、端口和文档链接仍然有效
3. 确认文案没有把规划中的能力写成当前事实
