## 二、讨论点逐项分析

### 1. Core Value Proposition — 图谱可视化的核心 UI 价值

**当前差距**: 图谱页面是用户直观感受"知识图谱驱动"的核心界面，但当前视觉品质远低于 Neo4j Bloom / Gephi 等专业工具给用户建立的心理预期。

**UI 视角**: 图谱可视化应该做到：
- **一眼看懂结构** — 节点层级、关系疏密通过视觉编码自然表达
- **一步到位交互** — hover 预览 → click 详情 → double-click 展开，渐进式信息披露
- **一致的设计语言** — 与白草药坛整体 UI 统一，而非"嵌入了一个三方图谱组件"的割裂感

### 2. Essential Features — 图谱视觉层必备能力

#### 2.1 有层次的节点色彩系统（参考 Neo4j）

Neo4j 的节点采用 **三元色组**：填充色 + 加深边框色 + 智能文字色。

**推荐 BaiCao 色板改造**：

```typescript
// 新版色彩三元组：[填充色, 边框色(加深20%), 文字色]
export const nodeStyleMap: Record<string, {fill: string; stroke: string; textColor: string}> = {
  Herb:      { fill: '#4C8EDA', stroke: '#2870c2', textColor: '#FFFFFF' },  // 蓝 - 核心药材
  Efficacy:  { fill: '#8DCC93', stroke: '#5db665', textColor: '#2A2C34' },  // 绿 - 功效
  Flavor:    { fill: '#F79767', stroke: '#f36924', textColor: '#FFFFFF' },  // 橙 - 性味
  Meridian:  { fill: '#C990C0', stroke: '#b261a5', textColor: '#FFFFFF' },  // 紫 - 归经
  Disease:   { fill: '#F16667', stroke: '#eb2728', textColor: '#FFFFFF' },  // 红 - 病症
  Component: { fill: '#57C7E3', stroke: '#23b3d7', textColor: '#2A2C34' },  // 青 - 成分
  Variant:   { fill: '#4C8EDA', stroke: '#2870c2', textColor: '#FFFFFF' },  // 蓝 - 变种
  Process:   { fill: '#D9C8AE', stroke: '#c0a378', textColor: '#2A2C34' },  // 米 - 炮制
  Trait:     { fill: '#DA7194', stroke: '#cc3c6c', textColor: '#FFFFFF' },  // 玫红 - 特征
  TimePoint: { fill: '#FFC454', stroke: '#d7a013', textColor: '#2A2C34' },  // 金 - 时间点
};
```

**关键改进**：
- 边框色比填充色降低 20-30% 亮度，产生微妙立体感
- 浅色节点(青、米、绿、金)用深色文字 `#2A2C34`，深色节点用白色文字
- 直接参考 Neo4j Browser 源码 GraphStyle.ts 的经典配色

#### 2.2 节点分级与视觉权重

```
中心节点:  size 60, borderWidth 3, 外发光阴影
同类药材:  size 42
一级关联:  size 32
二级关联:  size 24
```

中心节点增加 **外发光效果**（shadowColor + shadowBlur），替代目前的粗边框。

#### 2.3 边线样式分层

| 类型 | 样式 |
|------|------|
| 已验证关系 | 实线 2px，色 `#8DCC93`(草绿) |
| 待验证关系 | 虚线 1px，色 `#A5ABB6`(灰) |
| 悬停高亮 | 线宽 +1px，色彩加深 |
| 选中关系 | 线宽 3px，两端节点同步高亮 |

标签采用 **白底圆角胶囊** 而非直接贴在线上，避免叠压。

#### 2.4 交互层（渐进式信息披露）

```
Hover  → Tooltip（名称 + 类型 badge）
Click  → 右侧详情面板滑入
DblClick → 以该节点为中心展开下一层
右键   → 上下文菜单（查看详情 / 搜索相关 / 申请验证）
```

### 3. Frontend Features & Views — 图谱视图改造方案

#### 3.1 画布区域

**背景**: 从纯白改为极浅灰 `#F8F9FA`，增加网格点（`radialGradient` 或 CSS dots pattern），提供空间深度。

**缩放指示**: 左下角显示缩放级别 + 小地图（minimap），帮助用户在复杂图谱中定位。

**工具栏**: 左下角浮动工具条:
- 放大 / 缩小 / 适应画布
- 框选 / 自由拖拽模式切换
- 全屏

#### 3.2 右侧详情面板改造

**现状**: `Descriptions bordered` — 数据库后台风格。

**改造方向**: 参考 Neo4j Bloom Inspector 的卡片式设计：

```
┌─────────────────────────┐
│  🌿 人参                 │  ← 大字标题 + 类型 icon
│  Herb · 已验证           │  ← 副标题行: 类型Tag + 状态Tag
├─────────────────────────┤
│  来源    中国药典(2020)  │
│  分类    补气药          │  ← Key-Value 无边框列表
│  拉丁名  Panax ginseng  │
│  描述    五加科植物...   │
├─────────────────────────┤
│  ▸ 关联节点 (11)        │  ← 可折叠的关联列表
│    → 功效: 大补元气      │
│    → 归经: 脾经、肺经    │
│    → 成分: 人参皂甙Rb1   │
├─────────────────────────┤
│  验证信息               │
│  ID  444444...           │  ← 折叠区，默认收起
│  时间 2026/3/21          │
└─────────────────────────┘
```

**关键**:
- 移除 bordered 表格，改为无边框 key-value 布局
- 增加关联节点折叠列表，方便从详情面板直接导航
- 验证信息默认折叠，减少视觉噪音

#### 3.3 图例改造为交互式过滤器

参考 Neo4j Bloom Legend Panel：

- 图例移至右下角浮动面板（可折叠）
- 每个类型显示计数（如 `Herb (3)`）
- **点击图例项** → 切换该类型的显隐
- **悬停图例项** → 其他类型透明度降至 30%
- 隐藏项的颜色圆点变为空心
- 面板可收起为一个小图标

#### 3.4 工具栏优化

当前的 depth select + 刷新按钮过于简陋：

```
┌──────────────────────────────────────────────────────────┐
│  人参 的知识图谱  │ 12 节点 · 11 关系 │   🔍  深度[1▾]  ↻  ⛶ │
└──────────────────────────────────────────────────────────┘
```

- 统计数字改为内联 badge（不再用 Ant Tag）
- 深度选择改为小号 Segmented 组件 `[1] [2] [3]`
- 增加搜索入口（聚焦到特定节点）
- 增加全屏按钮

### 4. User Stories & Acceptance Criteria

#### 用户故事 1: 图谱首次加载
> 作为中药研究者，我希望打开图谱页面时，看到节点颜色清晰、布局疏朗、标签可读的图谱，让我在 3 秒内理解核心药材的关系结构。

**验收标准**:
- 节点颜色采用三元色组，立体感明显
- 中心节点有外发光，一眼可识别
- 标签不重叠（至少 90% 节点标签可读）
- 载入有平滑过渡动画（从散点到力导向稳定态）

#### 用户故事 2: 探索关联关系
> 作为中药研究者，我希望悬停节点看到快速预览，点击看到详细信息，双击展开下一层，不需要手动调整深度。

**验收标准**:
- Hover 显示 tooltip（名称 + 类型）
- Click 右侧面板滑入详情
- 关系线 hover 显示关系类型标签高亮

#### 用户故事 3: 按类型筛选
> 作为中药研究者，我希望通过图例快速过滤只看功效或只看归经的关系子图。

**验收标准**:
- 图例项可点击切换显隐
- 悬停图例项其他类型降低透明度
- 过滤后布局自动重排

### 5. Success Metrics

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 首次有意义交互时间 | < 3s | 从页面加载到用户首次点击节点 |
| 标签可读率 | > 90% | 节点标签未被遮挡的比例 |
| 视觉品质评分 | ≥ 4/5 | 用户调研打分 |
| 探索深度 | 平均 ≥ 2 层 | 用户平均展开深度 |

## 三、实现优先级建议

### P0 — 立即改善（视觉基础）
1. **节点色彩系统升级** — 三元色组替换纯色平涂
2. **中心节点外发光** — 替代粗描边
3. **边线分层样式** — 已验证实线 vs 待验证虚线
4. **开启布局动画** — 移除 `animation: false`
5. **画布背景** — 纯白 → 极浅灰 + 点阵

### P1 — 体验提升（交互层）
6. **Hover tooltip** — 节点/边悬停预览
7. **详情面板改造** — 卡片式替代 bordered 表格
8. **图例交互化** — 点击过滤 + 悬停高亮

### P2 — 高级功能（锦上添花）
9. **缩放工具栏 + Minimap**
10. **右键上下文菜单**
11. **双击展开下一层**
12. **搜索聚焦节点**

## 四、技术约束备注

- 当前使用 `@ant-design/graphs` 的 `NetworkGraph`，底层为 G6 v5。所有样式改造需在 G6 v5 API 范围内实现。
- 节点外发光通过 G6 的 `shadowColor`/`shadowBlur` 属性实现。
- Tooltip 通过 G6 的 `tooltip` plugin 或自定义 `behaviors` 实现。
- 边线虚线通过 `lineDash: [4, 4]` 实现。
- 图例交互需自行实现（G6 不内置图例过滤），通过 zustand store 管理可见类型 → 过滤 g6Data。
